# Synthetic fixtures

**Every number in this directory is SYNTHETIC. It is not mainnet data and was not read from any NEAR node.**

The files are generated by `go run ./cmd/verify/gen` (code in `internal/fixturegen`) and are
byte-for-byte reproducible; a unit test fails if they drift from the generator. Do not edit them by hand.

What they are: recorded JSON-RPC exchanges (`rpc-*.json`, the format `rpc.WithRecorder` writes)
shaped like NEAR responses: `block` with `finality: final`, then `query`/`call_function` for
`mt_batch_supply` on `intents.near` and the held-balance method of every token, all at one `block_id`
per round. 12 rounds, 30 blocks apart, starting at the invented height 1000030. Block hashes read
`SYNTHETIC-HASH-...`. Provider name: `synthetic`.

`expected.json` is what `make verify` compares against. It was computed by an independent oracle in
the generator (plain big-integer counting from the scenario definition), not by the alert code under test.

| Token | Decimals | Behaviour |

| USDC (`nep141:usdc.synthetic.near`) | 6 | healthy, small growing surplus |
| USDT (`nep141:usdt.synthetic.near`) | 6 | healthy, held exactly equals owed |
| ETH (`nep141:eth.synthetic.near`) | 18 | SUSTAINED DEFICIT: gap < 0 from round 5 to the end (K+1 = 5 or more rounds); deficit grows at round 9 |
| WBTC (`nep141:wbtc.synthetic.near`) | 8 | deficit for rounds 2-6 (turns red), then fully recovers |
| DAI (`nep141:dai.synthetic.near`) | 18 | FALSE ALARM: a single in-flight negative snapshot at round 6 that recovers at round 7 |
| hUSDT (`nep245:hot.synthetic.near:56_SYNTHETIC`) | 18 | the one NEP-245 token (multi-token standard), healthy |

A real capture goes in `evidence/fixtures/live-<block>/` (see `go run ./cmd/verify -capture`).
